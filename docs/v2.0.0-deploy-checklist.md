# integrasipaman v2.0.0 — deployment & verification checklist

> Target: GLPI-SERVER (GLPI 11), upgrading from **v1.11.1**.
> Written for whoever deploys and verifies this release on the VM.

**Why this is a major version.** Access control changes. Every page moves off
core `config` UPDATE onto the plugin's own right
`plugin_integrasipaman_config`, and the plugin's Setup UI moves into the shared
**PGN Suite** tab on Setup → General. Nobody should lose access (the installer
seeds the new right from each profile's existing core `config` mask), but the
places where access is *granted* change, so this needs a real look after the
upgrade, not just a smoke test.

## What's in it

| Area | Change |
|---|---|
| Command Audit Report (Piece 4) | New tab on *Tools → JumpServer Integration*: period picker, KPI strip, 5 summary tables, paginated high-risk detail, CSV/Excel/Print export per report, full command-log CSV. |
| Rights | New right `plugin_integrasipaman_config` (READ / UPDATE) + rights matrix tab on **Administration → Profiles**. |
| Setup UI | Plugin config now also renders as a section inside the shared **PGN Suite** tab (Setup → General). |
| Dashboard cards | The 5 cards checked no rights at all; they now return empty for users without READ and are hidden from *Add widget*. |

## 1. Before the upgrade — record the current state

- [ ] Note which profiles hold core `config` UPDATE:
      `SELECT p.id, p.name, pr.rights FROM glpi_profilerights pr JOIN glpi_profiles p ON p.id = pr.profiles_id WHERE pr.name = 'config';`
      These are exactly the profiles that can use the plugin today, and the set
      that must still be able to use it afterwards.
- [ ] DB backup (the install hook writes to `glpi_profilerights`).

## 2. Upgrade

```
sudo -u nginx php /data/www/glpi/bin/console plugin:install integrasipaman --force
sudo -u nginx php /data/www/glpi/bin/console plugin:activate integrasipaman   # if needed
```

- [ ] Setup → Plugins shows **2.0.0**.
- [ ] **Log out and log in again** before checking menus — the sidebar is cached
      in the session.

## 3. Rights

- [ ] Administration → Profiles → *(a profile)* → tab **JumpServer Integration**
      shows a Read/Update matrix and a Save button.
- [ ] Changing a checkbox and saving persists across a reload.
- [ ] Every profile recorded in step 1 now shows Read + Update checked.
- [ ] A profile with **no** core `config` right shows nothing checked.
- [ ] Re-run `plugin:install --force` once more and re-check: a profile you
      narrowed by hand keeps its value **unless** it holds core `config`
      UPDATE. Super-admin profiles are re-granted the full mask by design — to
      have a restricted PAM administrator, use a profile *without* core `config`
      UPDATE.

## 4. The new access path (the point of the release)

- [ ] Create a test profile with **no** core `config` right, give it Read +
      Update on JumpServer Integration only, and assign it to a test user.
- [ ] That user sees **Tools → JumpServer Integration** and can open PBI
      Insights, the Command Audit Report, and the activity log.
- [ ] That user **cannot** open Setup → General.
- [ ] Setup → Plugins → JumpServer Integration Dashboard → *Configure* opens the
      standalone config page for them (no redirect), and Save works.
- [ ] A user with **neither** right gets Access Denied on
      `front/pbi.php`, `front/export.php`, `front/reportexport.php`,
      `front/config.form.php`, `front/correlation.php`, `front/reeval.php`,
      `front/backfill.php`, `front/assetmap.php`, `front/usermap.php` — check by
      direct URL, not just by the absent menu entry.
- [ ] Give the test user **Read only** (no Update): the config page opens
      read-only (no Save button, no *Re-evaluate now*), and a hand-crafted POST
      to `front/config.form.php` is denied.

## 5. PGN Suite tab

- [ ] As an admin with core `config` READ: Setup → General shows exactly **one**
      **PGN Suite** tab, with a *JumpServer Integration* section in the left
      sub-nav. (⚠️ This is the first deploy with **two or more** participants on
      this instance — confirm there is one tab, not two.)
- [ ] Saving from inside the tab returns to the tab with the JumpServer section
      still selected, and the values persisted.
- [ ] Setup → Plugins → *Configure* redirects that admin to the tab.
- [ ] `lib/pgnsuite/ConfigTab.php` on the VM hashes to
      `347D56C91508E53326C8D4DE74105628D0FD535BDE619FE8A94EB147A448CBD6`
      (`sha256sum /data/www/glpi/plugins/integrasipaman/lib/pgnsuite/ConfigTab.php`).
      A different hash means the archive or the transfer converted line endings.

## 6. Command Audit Report

- [ ] Tools → JumpServer Integration shows two tabs; **Command Audit Report**
      defaults to the newest month that has data.
- [ ] KPI strip totals match the period; the "awaiting classification" note
      appears only when the eval cron is behind.
- [ ] Month picker and the custom from/to range both re-render the period.
- [ ] Each summary card's CSV / Excel / Print download opens with the right
      filename stub (`YYYYMMDD_YYYYMMDD_<REPORT>`), and Excel opens without a
      format warning.
- [ ] High-risk table: column sorting, and the pager on a period with > 100
      high-risk rows. `?hr_page=9999` lands on the **last** page, not an empty
      table.
- [ ] *Full command log* CSV downloads for a whole month without a timeout.
- [ ] A custom range longer than 366 days is capped, with the note shown under
      the period picker.

## 7. Regression (v1.11.x behaviour that must not change)

- [ ] The 3 automatic actions still run: Setup → Automatic actions, check
      `PluginIntegrasipamanCron`, `PluginIntegrasipamanTerminalPull`,
      `PluginIntegrasipamanRiskEval` last-run times after an hour.
- [ ] Activity log (`front/export.php`) still lists events and exports.
- [ ] Correlation page and the asset/user mapping lists still load and save.
- [ ] Dashboard cards still render for an admin; add one to a dashboard as a
      user **without** the plugin right and confirm it shows 0 / empty rather
      than real counts.
